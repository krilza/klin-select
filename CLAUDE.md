# KLIN SELECT

Интернет-магазин одежды, часов и техники напрямую с заводов Китая (Иваново). Статический сайт без сборки: HTML, CSS и JS открываются как есть. Заказ уходит в Cloudflare Worker, оттуда в Telegram-бот. План развития (сервер, БД, Docker) обсуждался отдельно, в репозитории его нет.

## Структура

- `index.html` — вся разметка. Страницы это секции `#tab-home`, `#tab-catalog`, `#tab-product`, `#tab-contacts`, `#tab-cart`, `#tab-privacy`, показывается одна.
- `css/style.css` — все стили, токены в `:root` (бумага `--ivory`, чернила `--black`, тонкие линии `--line`, скругление `--radius`).
- `js/products.js` — каталог (`PRODUCTS`). Единственное место, где живут товары.
- `js/app.js` — каталог, карточка товара, галерея, лайтбокс, корзина, оформление заказа, навигация.
- `images/` — фото товаров.

## Как устроено

- **Навигация** по хэшу: `#home`, `#catalog`, `#contacts`, `#cart`, `#privacy`, `#product/<id>`. Переключает `switchTab()`, разбирает адрес `routeFromHash()`.
- **Корзина** хранится в `localStorage` (`klin_cart`) только как `{id, selectedSize, qty}`. Название и цену всегда берём из каталога по `id`.
- **Товар** (`products.js`): обязательные `id`, `name`, `description`, `price`, `images`, `sizes`, `category` (`clothes` / `watches` / `tech`). Необязательные: `authenticity` (`original` / `replica`), `soldOut` (список размеров), `sizeChart`, `hidden`. Первое фото показывается в каталоге, второе проявляется при наведении.
- **Заказ**: `submitCheckout()` в `app.js` отправляет JSON на `WORKER_URL`. Worker должен сам считать сумму по `id`, а `price` и `total` из браузера использовать только для сверки.
- Версия кэша `APP_VERSION` в `app.js`: при её смене чистятся устаревшие ключи `localStorage`, корзина не трогается.

## Правила

- Комментарии в коде и тексты на сайте пишем по-русски. Стиль комментариев: короткие, объясняют «почему».
- Цвета, отступы и скругления берём из токенов в `:root`, а не пишем числами. Новый компонент должен выглядеть как остальные: тонкая чёрная линия, скругление 12px, заглавные буквы с разрядкой в подписях.
- Перед правкой вёрстки смотрим результат на трёх ширинах: 1440, 900 и 390. Особенно ловим двойные линии (граница блока плюс граница соседа) и переполнение по ширине.
- Новых зависимостей и сборки не добавляем без обсуждения: сайт должен открываться двойным кликом по `index.html`.
- Не коммитим служебное и черновое: скриншоты, `roadmap`, сравнительные страницы. Рабочие файлы кладём во временную папку.

## Окружение (Windows)

- Node.js, npm-кэш, Wrangler и браузеры Playwright стоят на диске D: `D:\Tools\`. Playwright MCP подключён к этому проекту.
- В PowerShell `npm` требует политики `RemoteSigned` для текущего пользователя (уже включена).
- Скриншоты: headless Edge или Playwright. Мобильную ширину меньше ~500px через Edge делаем оборачиванием страницы в `<iframe>` нужной ширины. Подробности в скилле `site-check`.
- Wrangler пока не авторизован (`wrangler login` не завершён), поэтому код Worker'а `klin-select-order` отсюда не виден.

## Скиллы проекта

- `site-check` — проверка вёрстки на разных ширинах.
- `add-product` — добавить товар в каталог.
- `run-site` — запустить сайт локально.
